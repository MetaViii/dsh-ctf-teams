## 使用流程

1. 使用 `ctf_teams_hypothesis(propose)` 登记一个可检验的主张及预测，并考虑另一个可以解释相同现象的假设。
2. `ctf_teams_experiment(next)` 读取当前代际引用。用 `plan` 写入 `hypothesis_id`、可选 `alternatives`、稳定的 `coverage_key`、`method`、`if_true`、`if_false`、`kind`、`estimated_seconds`，以及可选的 `budget_seconds` / `max_runs`。
3. 再读 `next`，先考虑低成本对照；用 `ctf_teams_exec(experiment_ref: ...)` 执行选中的实验。成员仍须带当前 `task_id` / `attempt_id`。
4. 读取作业和完整日志。作业结束后 `report` 写入原始观察、`validity`、`outcome`、`basis`，可附文件哈希；它沿用假设台账的追加和幂等规则。
5. 队长以 `review` 引用具体 `test_ids` 与理由裁决假设。确认反证后，相关假设的后续实验会被阻止，已运行的绑定分支也会保存停止决定并取消作业；不自动宣判题目不可解。裁决只发布一次共享看板更新，重复请求不制造新轮次。队长用 `release` 明确结束当前路线，或在复核前提后用 `reopen` 开启有界的新周期。均须当前修订号与具体理由。

`plan` 同题相同 coverage_key 返回既有计划，不覆盖原方法、归属或预算。修改输入／目标／参数后应使用新的覆盖标识；单纯换成员不算新的实验。计划和观察是数据，不是额外的系统指令。

## 选择与反证

短名单按估算成本分为不超过 30 秒、不超过 120 秒、其他三档，再比较对照实验、声明可区分的其他假设数量、估算时间和创建顺序。最多展示 5 个候选和 10 个待复核项，完整计划可分页读取。规则透明，不生成“信息增益概率”或假装了解漏洞成功率；模型可以结合题目合理选择另一项。

一个 500 响应既可能来自输入、认证、数据基数或题目服务故障。低成本对照应改变能区分解释的条件，而不是直接把“服务坏了”写成共享事实。队长的 supported/refuted/inconclusive 裁决引用实际试验及其当前修订，不按重复报告次数投票。

`validity: infrastructure/invalid` 必须配 `outcome: inconclusive`，不能支持或反驳科学假设。两个最新有效试验连续无结论、且尚未在当前修订复核时，需要队长重新评估后才可继续该假设。普通聊天、重复发现、无效测试不会计作科学突破；旧报告没有 validity 时保留原语义并视作待人工判断的实验报告。

## 停损执行边界

- 默认每个计划每周期最多 3 次 Docker 命令、300 秒活动墙钟时间，可设为 1..20 次和 1..3600 秒。估算时间不能高于预算。
- 从首次受管命令启动前开始计时，包含命令间模型思考／等待。命令的实际 deadline 不超过剩余预算，后台命令也受约束。预算耗尽后不再接受新命令；保留进程结果和文件。
- 按队伍锁原子登记预算，在容器启动锁内预留一次命令；并发调用不能多扣或超发。停止与修改通过同一团队授权重新读取当前状态。
- 每个执行者有持久化的当前实验。省略引用、切换计划、重建相同 coverage_key 不能清除这个边界；需要队长明确释放或重开。未选用实验计划的旧执行保持兼容，不能将其描述为所有解题工具的全局硬预算。
- `stop` 先持久阻断路线，再取消其作业；取消失败明确返回，不声称清理完成。`report/release/reopen` 在作业仍运行时拒绝。只读模式可读计划并停止自己的受管作业，不允许新计划、报告、裁决或执行。
- 面板暂停冻结时钟并停止容器。继续保留台账，不重放命令。任务代际已经变化时，队长须提供 `bind_task_id/bind_attempt_id` 才能重绑实验；可显式指定新的 owner。旧周期与决定保留。
- 超时不自动等同于假设被反驳，预算耗尽不自动标任务 failed，不触碰平台 flag 判定，不增加定时轮询或模型唤醒。

本轮复用 0.1.36 工具镜像。未更换 Desktop、权限、模型路由或其他插件。

## 验证与未覆盖项

针对性测试覆盖成本排序、同题去重、旧代际和成员隔离、原子预算、引用省略／替换、暂停与显式重绑、无效结果与科学反证分离、低收益复核和追加历史。真实 DSH Code Mode 用 SQLite 合成基数对照产生实际输出，并验证并发预算只产生一份结果、反证后高成本路线被阻止和运行中作业被取消，以及一秒实验预算终止十秒 sleep；恢复后台账和冻结的预算仍在。数据均为合成，不含实际题目、flag 或凭据。

测试同时收紧了脚本模型的成功断言：检查真正的工具结果、错误位和外部文件，不采信模型自己重复的通过标记。开发探针发现项目目录继承的受保护 ACL 使宿主的 workspace-write 准备失败，最终在独立临时目录验收，没有修改用户或项目 ACL。成员常驻提示仍控制在原有 600 字节门限内；完整指导在队长和工具文档中。

这不是通用语义执行器：实验设计、覆盖键、成本和裁决理由由模型／队长提供，插件不能保证它们正确。原生 shell、文件工具、其他插件、单条命令内部的循环及模型 token 不属于命令次数硬配额；时间上限仍约束受管 Docker 命令。主动脱离进程组的程序沿用整容器暂停兜底。强杀宿主后未冻结的时钟会保守耗尽，要求人工复核，不自动续预算。

未进行带真实模型、同题同预算的对照评测；不将功能测试通过换算为解题率收益。真实平台写操作、GUI 手动刷题与其他操作系统仍需单独验证。

本机交付采用同一 SHA-256 安装包，174 个包文件逐字节一致；既有会话、战队、工具成果、权限和模型路由保持。大型成果树先完成可续传复制，再以固定内存逐文件验证两端 SHA-256，保留链接与原修改时间；失败的初始备份不作为可恢复交付记录。DSH 已重开，既有战队文件哈希保持；不自动恢复工作。具体计数及测试范围见 validation.json。
