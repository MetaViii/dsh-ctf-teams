## 本轮实现

| 问题 | 处理 |
| --- | --- |
| Windows 检查无法反映 WSL | `ctf_teams_env` 增加 `runtime` 与 `distribution`。未指定发行版只列名称，不自动启动默认或 Docker 发行版；明确选择后先验证 Linux 能启动。 |
| WSL 输出与 Python 混用 | argv 调用，不拼接 shell；解析 UTF-16LE 名称，Windows `env.pythonBin` 不传入 Linux。报告解释器与搜索范围。Linux 系统目录和用户 `.local/bin`、`bin` 之外不作全局缺失承诺。 |
| 探针失败误报缺失 | 超时、进程错误和查找器异常返回 `unknown`，不加入缺失工具自动安装集合。WSL 调用跨 lane 串行，避免无界并发。发现真实超时仍保留诊断，不能说底层 WSL 故障已完全解决。 |
| 失败数据或不完整扫描覆盖缓存 | CLI `--output` 只在有效、完整响应后创建同目录临时文件，写入并同步无 BOM 的 UTF-8 JSON，再原子替换。限流、HTTP/协议错误、部分扫描和写入失败保留旧数据。 |
| 限流别名遗漏 | 识别明确错误信封中的 `RATE_LIMIT_EXCEEDED`；不扫描题目源码或更改 flag，不自动重试提交。 |

安装只支持原有本机流程；`runtime=wsl` 的 install 在执行前明确拒绝，不会误装到 Windows。WSL 命令依据 [Microsoft 官方文档](https://learn.microsoft.com/windows/wsl/reference)核对，并用本机 Kali 实测。探测包不存在不等于没有替代工具；版本信息和自测范围也不等于工具能完成所有题目。

CLI 原有 stdout 用法保留；`--output` 模式成功只在 stderr 给出路径和字节数。输入目录须已存在。多个 lane 应各写各的文件：原子替换不提供并发合并。`call` 仍可调用平台写工具；若写操作完成后输出落盘失败，需要查真实结果，不能自动重放。

## 验收与交付

本轮新增 7 个回归，涵盖真实 CLI 子进程与本地 MCP HTTP 夹具、缓存字节保留、UTF-8、分页不完整、WSL 平台/解释器隔离和探针失败。真实 CodeMode 场景验证新参数与返回结构，确保 WSL install 不转到本地安装。

最终命令、产物 SHA、宿主运行结果与仍未覆盖项见 [validation.json](./validation.json)。真实 Kali 的读取结果见 [WSL 实测](./evidence/wsl-real.json)；其中 `unknown` 就是未完成探测，不能计为已安装或缺失。

本次推送到维护者 GitHub fork，未发布 npm，未替换正在运行的 Desktop 安装，未恢复刷题、提交 flag 或改动平台和用户工作区。此前本地修复随源码一并整理；独立的用户删除项和未审查文件不混入提交。更改仓库元数据为维护者 fork，保留原作者署名与插件包身份。
