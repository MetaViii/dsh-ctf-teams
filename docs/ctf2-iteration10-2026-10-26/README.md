# 第十轮：0.1.34 实机反馈的选择性迭代

版本 `0.1.35`。反馈包含平台故障、模型路由故障和任务协议限制，不能把它们都当作同一种可自动重试的错误。用户数据和实际候选未纳入公开测试；所有验收使用隔离状态和合成题目。

## 选择结果

| 建议 | 本轮处理 | 边界 |
| --- | --- | --- |
| A1/A2：故障看不出下一步、405 成因混杂 | 状态给出结构化 `recovery`；分配等待回执含 `next_action` 和已知 `retry_at`，区分明确的 IP/套餐/并发/频率提示。 | 诊断来自错误报告；不会推断账号权益，不编造恢复时间。无 `same_route` 别名，原 API 已支持同路由修复。 |
| A3：重启后代理不可达 | 暂不加入自动 watchdog。 | 代理的授权、工作区及进程生命周期需独立治理；避免再次引入自动唤醒循环。 |
| A4：格式数组变字符串 | 原本就支持真数组。本轮补上 JSON 字符串数组在写入及旧数据读取时的兼容，普通正则字符类保持有效。 | 既有告警是登记时记录，不修改候选原文或伪造“平台接受”。 |
| A5：内联任务没有 CTF 上下文 | 内联 API 接受 `challenge_id/resource_key/preflight/preflight_finding_id`，按拓扑排序映射到实际任务；重复题目须显式允许。 | 不扩展命名配置模板的字段范围；有界原子校验失败时不归档旧工作。 |
| A6：下载脚本漂移 | 暂不新增跨平台下载包装器。 | 工作区私有脚本、平台附件授权与 TLS 故障不是同一接口；不未经平台验证复制运行配方。 |
| A7/B2：暂停只有消息、目标继续跑 | 面板走硬暂停：状态先落盘、旧尝试失效、任务回到可续做队列、保存历史结果，再取消队长并排空成员；宿主 `goals.get/pause` 可用时暂停当前目标。 | 仅处理当前队长会话的目标。旧宿主没有能力或能力失败时明确报告；战队仍停。继续战队不会自动恢复目标。 |
| A8：多余候选刷提示 | 保留显式裁决。 | 同题可能有多面合法 flag；一个 accepted 不能自动否定其他候选。 |
| A9/C2：题已接受，任务失败无法收尾 | 新增显式 `resolve_task`，要求当前任务尝试、同代际同题 verified 引用及完成整个任务的证据；原错误保存在 `resolution`，重复调用不改写。 | 只接受失败的普通 work，不跳过 review/repair/requirements，也不自动完成兄弟任务。verified 是队长已登记的裁决，本操作不联网独立核验。 |
| A10/B6：每题固定 whoami 与提交占配额 | 不加入每题自动平台调用或固定 sleep 配方。 | 不同平台的回执、分数和多旗语义不同；保留原始回执，由队长明确核对。 |
| B1：维护/传输失败变成解题失败 | 最终成员请求的 TRANSPORT、维护及 502/503/504 走基础设施故障策略；工作保持开放，一次冷却恢复后仍失败就等显式处理。 | 这是宿主成员请求错误分类，不替模型识别每个题目工具的业务 5xx，也不会无限重试。已被模型显式标 failed 的任务仍需重派或有证据收尾。 |
| B3：全局配额冲突 | 区分并发/频率限制，给出降并行或等待建议，支持修复时停发。 | 插件无法完整管理队长、原生子代理、外部 MCP 及其他会话的统一配额；不声称新增全局信号量或令牌桶。 |
| B4：修完马上撞限流 | `wake:false` 为持久化派发关闭状态，并覆盖调度、直接消息和委派入口；显式 `wake:true` 才清除。 | 默认仍为 true，保持旧 API 兼容；不要在服务未恢复时反复清故障。 |
| B5：工具目录被当作整机清单 | `env check` 返回明确 `inspection_scope`，协议强调 missing/unknown 不代表离线目录不存在。 | 本轮没有扫全盘或自动执行离线目录里的程序。 |
| C1：失败任务 ID 报废 | 经代码和实际工具核对，这个推断不成立：队长 `reassign_task` 已支持同 ID 重试失败任务。补充协议说明与回归。 | 成员不能擅自将终态重新认领；新尝试由队长撤销旧能力后建立。 |

面板“暂停”不调用模型；其他求解动作继续以受权限校验的会话请求执行。原聊天停止仍保留取消未完成任务的既有行为，面板暂停则保留待续任务。两者都先落盘停止边界，再取消执行，且保留文件和已记录工作。用户显式继续前，认领、重派和调度不得绕过 `halted`。

## 验证范围

针对性测试覆盖原子校验、冷读停发、错误分类、旧尝试拒绝、显式继续和结果收尾。真实宿主探针会启动实际目标回合，发送经过 Connection 校验的 HTTP 暂停，检查磁盘战队状态和真实 GoalService 状态，并观察暂停响应后是否还有模型请求；重复暂停不增加目标版本。CTF Code Mode 流程的最终结果由进程外读取持久化记录断言。

完整回归、最终 tarball 哈希、宿主矩阵和本机安装结果验收后记录于 `validation.json` 和 `evidence/`。真实模型解题率、用户窗口交互、在线平台提交、其他操作系统及全局配额管理仍未验证。
