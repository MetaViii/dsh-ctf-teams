# v0.1.28 — hand over the challenge, the solve starts itself

Staged plans were a review step the user never wanted: give the panel a
challenge description / attachments / URL, and the squad should just go until
the flag is verified.

## `autoApprove` (default true)

A new plugin config option, set in `cordis.patch.yml`:

```yaml
- id: ctf-teams
  config:
    autoApprove: true   # default: create-and-run
```

With it on, every activation path asks for `approval="automatic"`:

- **the captain protocol** (`usageSectionText`) — "the plan you submit in that
  call is the plan that runs — never stage it, never wait for a confirmation
  turn, and start dispatching immediately", plus a *Run to the flag* rule: the
  first quiet moment is not the end of the solve while open tasks or live lanes
  remain;
- **the `/ctf-teams` activation directive** (`buildActivationDirective`) — the
  gesture boundary now tells the captain to create with `approval="automatic"`
  and keep working through ready tasks and member reports;
- **the 解题面板 开始解题 form** — its prompt says
  `ctf_teams_create(approval="automatic")` in the same call as the roster and
  DAG, no staged plan, no waiting; the form's own note says the solve starts
  without an approval click.

`autoApprove: false` restores exactly the previous behaviour: `approval="required"`,
the Web plan card, and the 批准并运行 button as the gate. The button itself stays
in the panel, so an already-staged team (created before this release, or by a
profile with the gate on) can still be approved with one click.

The panel reports the mode in its payload (`autoApprove`), so the start form
tells the truth about what will happen next.

## Nothing else changes

The approval machinery is untouched — `ctf_teams_approve`, the staged phase and
the plan-review flow all still exist and are still exercised by the gates. This
release only changes what the *instructions* ask for by default, plus the panel
wording.

## Gates

- `verify` — the protocol text must ask for `approval="automatic"` / "never
  stage it" / "Run to the flag", contain no `approval="required"`, and restore
  the staged wording (with "two-phase") when `autoApprove: false`.
- `lifecycle-verify` — the activation directive is asserted in both modes: auto
  by default, staged review when the flag is off.
- `verify:dashboard` — a start request from the panel must produce the
  create-and-run prompt, and `autoApprove: false` must produce the staged one.
- `verify:client` — the start form says 建队并立刻开跑 / 不需要你点批准.

## Upgrade

Reinstall into the profile and restart the Host / Desktop app.

```bash
dsh plugin --profile <name> add @nanmicoder/dsh-ctf-teams
```
