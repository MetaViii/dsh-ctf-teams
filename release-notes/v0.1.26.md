# v0.1.26 — the dashboard becomes operable

The 解题面板 was read-only. It now drives the solve: start a challenge, approve a
staged plan, pause/resume, verify a flag, attach files, write or export the
writeup — without leaving the tab.

## The interaction model

Every control composes **one user turn in the session** and nothing else. The
panel never writes team state: the captain agent stays the only writer, so the
existing protocol (staged approval, flag verdicts, `ctf_teams_set_challenge`)
keeps applying, and the action shows up in the transcript as the user's own
message — a later reader can see exactly what was clicked.

The endpoint is therefore not a generic "run this prompt" gadget: the client
sends an action name plus typed parameters, and the host validates them against
durable state before composing the instruction.

| Button | When | Turn it queues |
|---|---|---|
| 开始解题 | no team | a form (goal, profile, remote, category, points, flag format) → `/ctf-teams …` + the recorded challenge facts |
| 批准并运行 | staged, captain | `ctf_teams_approve` + dispatch ready tasks |
| 推进一轮 | running | `ctf_teams_status`, dispatch ready work, wake lanes that are behind |
| 暂停 / 继续 | running / halted, captain | halt / `ctf_teams_resume` with a reason |
| 核对 flag fN | a candidate exists, captain | platform check, then `ctf_teams_mark_flag` |
| 附件 | not archived, captain | a workspace file picker → `ctf_teams_set_challenge` with the picked paths |
| 写 WRITEUP | participant | write the reproducible chain to `WRITEUP.md` |
| 导出 WP / 导出复盘 | always | browser download of `WRITEUP.md` or a generated review report |

An archived team is read-only (exports only); captain-only buttons are disabled
for a member instead of failing later; there is deliberately **no one-click
archive/delete** — discarding unfinished work stays a captain decision.

## What changed

- `src/dashboard-actions.ts` — the closed action set: validation, authority
  requirement, server-side prompt composition, the bounded workspace file
  listing, and the review-report renderer.
- `src/dashboard-route.ts` — three new trust-fenced endpoints next to `…/state`:
  `POST …/action`, `GET …/export`, `GET …/files`. Bodies are size-limited,
  methods whitelisted, and authority checked against durable state
  (`team.captainSessionId`) rather than the caller's claim.
- `src/client/entry.js` — the action bar, the start form, the attachment picker
  (filter + sizes), download handling, and inline success/error feedback.
- `scripts/dashboard-route-verify.mjs` — extended from 21 to 38 checks: happy
  paths, every refusal (403/404/405/409/400/413), free-form prompt text never
  forwarded, export/report/files payloads, plus the trust fence.
- `scripts/client-verify.mjs` — a stateful hook runtime so the gate can click
  buttons: approve/nudge/verify post the right action, exports download, the
  start form posts what was typed, the picker lists and submits files, member
  and archived views behave.
- Skipping `dist/` in the file picker was a bug the new gate caught: shipping a
  challenge as `dist/` is common, so only `node_modules`, `.git`, `.ctf-teams`
  and `.dsh` are skipped.
