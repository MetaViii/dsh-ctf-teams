# v0.1.23 — the `ctf-teams` agent preset mode

The plugin now ships its own **DeepSeek Harness agent preset**, so the squad is
a selectable mode instead of a tool set you have to remember to invoke.

## What changed

- **New bundle layer:** `presets/ctf-teams.patch.yml` declares an
  `@deepseek-ai/dsh-agent-preset` row (`id: ctf-teams`, `name: CTF 团队模式`,
  `order: 3`). `package.json` `dsh.bundle.patch` now lists both patch files in
  order (host plugin row first, preset declaration second), and `files[]` ships
  the `presets/` directory.
- The preset composes a full agent plane — persona, shell, filesystem, skills,
  goals, plan mode, compaction, delegation (continuable `subagent` + `subagent_fork`),
  todo/ask-user/web/present — mirroring the shipped `standard` preset key for
  key, with a CTF captain persona on top.
- `cordis.patch.yml` is unchanged in behaviour: the host-plane plugin row still
  registers `ctf_teams_*`, the `/ctf-teams` + `/ctf-teams-board` commands, and
  the captain usage section for every session of the profile.

## Dashboard, read at a glance

The terminal panel gained the counters and the one actionable line it lacked:

- Every section bar carries its own live counter: `Agents … 1/4 working`,
  `Task board … [████████████░░░░] 3/4 · last beat 30s ago`,
  `Findings (latest) … 3 total · newest 3m ago`, `Flags … 1 total · 1 verified`.
- A new `Next` row derives the single most useful action from the same state:
  verify a flag candidate, dispatch idle lanes that still have ready work,
  resume a halted team, approve a staged plan, or finish the writeup.
- `Status` reads `running · round 4 · 12m · 3 findings · 1 flag`; the working
  count moved to the section that owns it instead of being printed twice.
- `last beat` comes from the newest finding, flag or task update, so a stalled
  round is visible without reading timestamps.
- `truncateToWidth` no longer eats a string that exactly fills its column, so
  full-width rows and CJK findings stop showing a stray `…`.

## Why

Versions before 0.2.0-rc.2 discovered presets as directories under
`<dshHome>/.agent-presets/<id>/`. On 0.2.0-rc.2 a preset is a declaration row in
the composition (`@deepseek-ai/dsh-agent-preset`), listed by
`@deepseek-ai/dsh-agent-preset-registry` and rendered by the General-settings /
session mode picker. A plugin that only shipped a plugin row therefore added no
mode — this release adds the declaration.

Because the plugin row stays on the host plane (it is what the runtime lab and
legacy hosts compose), enabling the mode does not change any existing session.

The `/` menu cleanup and the earlier `ctf-teams-ctf-teams` alias removal shipped
in v0.1.24.

## Upgrade

Reinstall the package into the profile and restart the Host / Desktop app:
bundle patch layers are read when the composition loads, so the new mode appears
only after a restart.

```bash
dsh plugin --profile <name> add @nanmicoder/dsh-ctf-teams
```

On a host without the preset registry (0.1.x) the preset row cannot resolve; the
host-plane plugin row keeps working, and the mode selector simply shows nothing
new. Add `- insert: [{ id: ctf-teams, name: '@nanmicoder/dsh-ctf-teams' }]` to
that profile's `cordis.patch.yml` if you want the tools scoped there.
