# v0.1.35 — 硬暂停、可控修复与失败成果收尾

- 解题面板“暂停”直接进入共享运行时停止边界，不再依赖模型读消息。立即落盘 `halted`，撤销旧尝试、保留检查点和历史验证记录、排空成员执行；宿主目标服务可用时同时暂停当前会话目标。普通聊天停止的取消语义保持，面板暂停的未完成任务可在显式继续后续做。
- `update_member(wake:false)` 修复路由后持久关闭该成员派发入口，状态查询、调度、直接消息不能绕过；明确传 `wake:true` 才放行。旧调用省略 `wake` 保持原行为。
- 传输、502/503/504 和维护故障按基础设施策略处理，保留工作并限制自动恢复次数。状态与等待回执区分 IP 阻断、套餐、并发和频率限制，提供下一动作与已知恢复时间，不编造未知限流窗口。
- 内联 `plan.tasks[]` 支持题目 ID、资源锁、preflight 和证据引用，仍原子校验整个 DAG；同题第二角度需显式允许。
- 新增队长 `ctf_teams_resolve_task`：只对已失败的普通工作，使用同代际、同题目的已登记 verified flag 引用和具体完成证据显式收尾，保留原失败记录并防止旧尝试覆盖。重试未完工作仍用现有 `reassign_task`，无需换任务 ID。评审/修复/需求质量门禁不能用这一操作跳过。
- 格式规则继续支持数组，并兼容误传为 JSON 字符串的数组及其历史显示；保留候选原文和登记时的格式警告。环境检查明确标注只覆盖受管目录、PATH/Python 和选定运行时，不等于整机清单。

未加入自动代理 watchdog、全局 provider 配额管理、自动提交/平台回执采信或自动关闭同题候选。选择依据、验证和本机交付见[第十轮记录](../docs/ctf2-iteration10-2026-10-26/README.md)。未发布 npm。
