# v0.1.31 — 让失败实验也成为可复用的解题进度

本轮选择建议 §20、§27、§29 的共同问题：多条 lane 缺少可共享、能保留纠正历史的实验记录。版本号标识源码和候选包；没有向 npm 发布，也未替换用户当前 Desktop 安装。

- 新增成员与队长共用的 `ctf_teams_hypothesis`，支持按题目查询、登记假设和追加实验。记录可检验预测、方法、观察、支持/反驳/不确定结果、依据类型和下一步。
- 精确重复假设和带稳定 key 的实验重试不产生新进度；实验追加使用 revision 和团队代际引用，拒绝过期写入。相反报告全部保留，状态显示冲突数。
- 可选文件证据由插件读取工作区内实际文件，记录 SHA-256、大小和时间。显式查询检查最新实验文件的变更、丢失或不可读状态；拒绝路径越界与符号链接逃逸，限制文件大小和数量。哈希是完整性记录，不是推导正确性证明。
- 查询分页、历史摘要和归档支持续做与复盘。新增记录使用原有 finding 同步；读取和重复操作不改游标、不唤醒成员，暂停状态保持。
- 队长和成员协议加入实验前查重、测量反驳继续证伪和独立复现要求。没有新增任意命令执行器，也不自动执行模型给出的验证代码。

流程、证据和未覆盖项见 [第七轮迭代](../docs/ctf2-iteration7-2026-10-23/README.md)。
