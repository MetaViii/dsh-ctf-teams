# v0.1.29 — pick the challenge files when you start, not after

The 开始解题 form had no way to hand over the challenge's files: attachments
could only be added *after* a team existed, with the 附件 button. Now the form
carries them from the start.

## What changed

- **The start form has a 题目附件 section**: 选择附件 expands the same
  workspace list the 附件 action uses (filter, sizes, checkboxes), picked files
  show as removable chips above it, and the count rides on the button label.
  Submitting sends them with the goal / profile / remote / category / points /
  flag format, so the captain records the challenge — attachments included — in
  one `ctf_teams_set_challenge` call.
- **Shared picker internals** (`useWorkspaceFiles` + `FilePickerList`): the
  standalone 附件 dialog and the form now render the same component, so both
  show the same real paths and sizes from the host's listing.
- **Host-side validation**: attachment paths are client-supplied strings that
  end up inside an instruction, so the action route now checks every path
  against the workspace listing and refuses the request (400) when one is not
  an existing workspace-relative file. A path carrying newlines — i.e. an
  attempt to append instructions — fails that check instead of reaching the
  captain's prompt.

## Gates

- `verify:dashboard` — a start with `attachments: ['chal.zip']` puts
  `- 附件: chal.zip` in the prompt; `does/not/exist.txt` and a
  newline-smuggling path both answer 400.
- `verify:client` — the form shows the 题目附件 section and the file count,
  expanding it lists the workspace files, ticking one renders a removable chip,
  and submitting posts `attachments: ['dist/rsa.pem']` alongside the typed goal.
