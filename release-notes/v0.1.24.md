# v0.1.24 — a short, unambiguous `/` menu

## What changed

`registerCTFTeamsCommand` generated one slash alias per configured team profile
(`/ctf-teams-<name>`). Because the built-in squad is itself named `ctf-teams`,
the command menu showed `/ctf-teams` **and** a redundant
`/ctf-teams-ctf-teams`, and a team profile named `board` would have shadowed
`/ctf-teams-board`. Two generated names are now skipped, in `command.ts`:

- **The default profile's own alias.** The generic command already runs the
  configured `defaultProfile`, so `/ctf-teams-ctf-teams` and `/ctf-teams` were the
  same activation under two names. The alias survives when `defaultProfile: ''`
  disables the default squad, because it is then the only way to select the
  built-in roster explicitly.
- **Names this plugin owns.** `RESERVED_COMMAND_NAMES` (`ctf-teams`,
  `ctf-teams-board`) can never be taken by a generated alias, whatever a profile
  is called.

The menu is now, for the shipped configuration:

| Command | What it does |
|---|---|
| `/ctf-teams [--profile <name>] <challenge>` | Start or continue a solve; without `--profile` the default squad applies. |
| `/ctf-teams-board` | Dashboard into the transcript, no model turn. |
| `/ctf-teams-<profile>` | One alias per *other* configured profile (`ctf-teams-web-only`, …). |

`registerCTFTeamsCommand(ctx, getProfiles, { defaultProfile })` carries the new
option. `scripts/lifecycle-verify.mjs` pins all four cases: no alias for the
default profile, none for `board`, aliases kept for the rest, and the built-in
alias present again when the default is disabled.

## Upgrade

Reinstall into the profile and restart the Host / Desktop app.

```bash
dsh plugin --profile <name> add @nanmicoder/dsh-ctf-teams
```
